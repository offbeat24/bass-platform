# BASS product definition

## Product intent

BASS turns a natural-language product idea into a reviewable product-to-ship flow while preserving human ownership of direction, risk, and final judgment.

## Users and problem

Builders and small teams use several coding agents and harnesses but need one portable source of truth for what is being built, how work is divided, when loops stop, and what evidence supports completion.

## Value and success

- Connect to an empty or existing repository without replacing its native stack or instructions.
- Move from idea through PRODUCT, TECH, DESIGN, optional spec, tasks, implementation, verification, and review.
- Reduce prompt and validation waste through selected context, affected checks, bounded attempts, and evidence reuse.
- Let teammates continue from repository-local contracts rather than one person's chat history.

## Name and brand

BASS remains the product name. The 0.4 descriptor is “Portable Product-to-Ship Harness.” Visual identity and logo changes are proposals until explicitly approved.

## Scope

CLI core, Codex/Claude plugin skills and hooks, repository contracts, model alias recommendations, external provider boundaries, and read-only status observation.

## Non-goals

Web dashboard, TUI, autonomous approval, external harness installation, model hosting, or replacement of repository-native build and design systems.

## Open decisions

Evaluate a read-only 0.5 web console only after 3 project types, 20 tasks, 5 loops, parallel experience, team feedback, and a stable event schema.

## Decisions and history

- 0.3 established the portable adaptive runtime and exact-version plugin contract.
- 0.4 expands the contract from task execution to product shaping, bounded loops, evidence, and observation.
